# Fix: Timetable Engine Now Accurately Respects Credit Hours

## Root Cause
The old scheduler iterated **day → hour** sequentially, filling all hours on Monday before moving to Tuesday. A 3-credit-hour subject got placed at Monday 8:00, 9:00, 10:00 — **3 slots on 1 day** instead of **1 slot on 3 different days**.

## New Algorithm — Score-Based Greedy Placement

Instead of iterating sequentially, the scheduler now:

1. **Generates all valid candidate cells** `(day, hour, teacher)` for a subject
2. **Scores each candidate** using 4 weighted factors:
   - **Spread (+100)**: Strongly prefers days where this subject has **0 existing slots** — this is the primary fix
   - **Day balance (+10×)**: Prefers less-loaded days to balance the week evenly
   - **Programme balance (-5×)**: Penalises days already heavy for the target programme
   - **Time preference (+5/+2)**: Slight morning bias (8-12 ideal, 13-15 ok)
3. **Picks the highest-scored candidate** and places it
4. **Re-evaluates** after each placement (scores change as the board fills)

This ensures a 3-credit subject appears on **3 different days** (Mon/Tue/Wed), not 3 hours on Monday.
